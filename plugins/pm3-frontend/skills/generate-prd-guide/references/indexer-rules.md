# Indexer 规则 — PRD/API 交叉检索规范

> 本文件供 Indexer SubAgent 使用，包含 PRD 检索策略、API 检索策略、匹配置信度判定的完整规则。

---

## 1. PRD 检索策略

### 1.1 四轮搜索机制

对每个字段依次执行以下搜索：

```
第 1 轮：精确匹配 → 成功则停止
   ↓ 失败
第 2 轮：模糊匹配 → 成功则停止
   ↓ 失败
第 3 轮：上下文检索 → 成功则停止
   ↓ 失败
第 4 轮：通用规则检索 → 记录结果
```

### 1.2 第 1 轮：精确匹配

**搜索词构造**：
```
搜索词 = 字段中文名（原文）
```

**搜索范围**：PRD 全文

**匹配目标**：
- PRD 表格中的"字段名称"列
- PRD 文字描述中的"XX 字段"
- PRD 功能说明中的直接引用

**成功条件**：
- 找到与搜索词完全一致的字段名
- 或找到包含搜索词的完整字段定义

**示例**：
```
搜索词："申请单号"
匹配结果：PRD 表格中"字段名称"列包含"申请单号"
```

### 1.3 第 2 轮：模糊匹配

**搜索词构造**：
```
去掉通用后缀：
- "名称" → "项目"
- "编号" → "申请单"
- "号" → "单"
- "ID" → ""
- "码" → "审批"
- "日期" → "开工"
- "时间" → "批准"
- "类型" → "申请"
- "状态" → "审批"
```

**搜索范围**：PRD 全文

**匹配目标**：
- 包含词根的字段定义
- 字段的同义描述

**成功条件**：
- 找到包含词根的字段
- 上下文语义一致

**示例**：
```
搜索词："申请单"（来自"申请单号"）
匹配结果：PRD 中"申请单编号"字段
```

### 1.4 第 3 轮：上下文检索

**搜索词构造**：
```
搜索词 = prdKeyword 数组中的每个词
```

**搜索范围**：页面对应的 PRD 章节

```
列表页字段 → 限定在"5.1.5.2 开工申请 - 列表"章节
表单页字段 → 限定在"5.1.5.3 开工申请 - 表单"章节
详情页字段 → 限定在"5.1.5.4 开工申请 - 详情"章节
审批页字段 → 限定在"5.1.5.5 开工申请 - 审批"章节
```

**匹配目标**：
- 章节内的字段说明
- 章节内的业务规则描述

**成功条件**：
- 在限定范围内找到相关描述
- 语义与字段相关

**示例**：
```
搜索词：["申请单号", "申请单", "单据编号"]
搜索范围：5.1.5.2 开工申请 - 列表
匹配结果："列表查询条件支持按申请单号模糊搜索"
```

### 1.5 第 4 轮：通用规则检索

**搜索词构造**：
```
模块类型 → 关键词映射：
- search → ["查询条件", "筛选", "搜索"]
- table → ["列表说明", "表格", "列说明", "展示"]
- form → ["表单结构", "填报说明", "字段说明", "录入"]
- display → ["展示说明", "只读", "查看详情"]
- approval → ["审批意见", "审批节点", "审核"]
- attachment → ["附件", "文件上传", "材料"]
```

**搜索范围**：PRD 通用规则章节

**匹配目标**：
- 通用字段规范
- 通用校验规则
- 通用组件规范

**成功条件**：
- 找到适用于该模块类型字段的通用规则

## 2. PRD 提取内容

找到匹配后，提取以下信息：

```json
{
  "fieldName": "PRD 中的字段英文名",
  "section": "PRD 章节号（如 5.1.5.2）",
  "anchor": "PRD 锚点（如#5152-开工申请列表 - 查询条件）",
  "rules": {
    "required": "Y/N/条件必填：[条件]",
    "readonly": "Y/N/条件只读：[条件]",
    "maxLength": "最大长度",
    "precision": "精度（如 2 位小数）",
    "format": "格式（如 yyyy-mm-dd）",
    "dict": "字典编码",
    "searchType": "搜索类型（如模糊搜索）",
    "autoFrom": "自动带出来源",
    "linkage": "联动逻辑描述"
  },
  "description": "字段说明原文",
  "confidence": "high/medium/low"
}
```

### 2.1 字段英文名提取

**优先级**：
1. PRD 表格中"字段名/英文名"列
2. PRD 文字描述中的"英文名"、"字段编码"
3. API 文档中的字段名（如有 API 检索）
4. 无法找到时，生成拼音首字母（如"申请单号" → "sbdh"）

### 2.2 必填规则提取

**提取逻辑**：
```
"必填"、"必须"、"不能为空" → required = "Y"
"非必填"、"可选"、"选填" → required = "N"
"XX 情况下必填" → required = "条件必填：[XX 情况下]"
未提及 → required = "N"
```

### 2.3 只读规则提取

**提取逻辑**：
```
"只读"、"不可编辑"、"系统自动" → readonly = "Y"
"可编辑"、"手动输入" → readonly = "N"
"XX 节点只读" → readonly = "条件只读：[XX 节点]"
未提及 → readonly = "N"
```

### 2.4 精度/格式提取

**容量字段**：
```
"MW"、"万千瓦" → precision = "2 位小数"
"MWh" → precision = "2 位小数"
"万元" → precision = "2 位小数"
"元" → precision = "2 位小数"
```

**日期字段**：
```
"日期" → format = "yyyy-mm-dd"
"年月" → format = "yyyy-mm"
"时间" → format = "yyyy-mm-dd HH:mm:ss"
```

### 2.5 字典提取

**提取逻辑**：
```
"字典"、"枚举"、"下拉选择" → 提取字典编码
"业态" → dict = "project_format"
"审批状态" → dict = "approval_status"
"是/否" → dict = "boolean"
```

## 3. 按钮 PRD 检索策略

### 3.1 两轮搜索机制

对每个按钮执行：

| 轮次 | 搜索策略 | 搜索范围 |
|------|---------|---------|
| 第 1 轮 | 按钮名称 + "按钮" | PRD"按钮逻辑"章节 |
| 第 2 轮 | 按钮名称模糊匹配 | PRD 全文 |

### 3.2 按钮提取内容

找到匹配后，提取：

```json
{
  "section": "PRD 章节号",
  "anchor": "PRD 锚点",
  "displayCondition": "显示条件",
  "validate": "点击校验规则",
  "action": "点击行为",
  "successResult": "成功结果",
  "failResult": "失败结果",
  "position": "按钮位置",
  "confidence": "匹配置信度"
}
```

## 4. API 检索策略（如有 apiDocPath）

### 4.1 API 文档格式支持

| 格式 | 解析方式 |
|------|---------|
| Swagger/OpenAPI JSON | 直接解析 JSON |
| Markdown 表格 | 解析表格提取字段 |
| Markdown 文字描述 | 正则提取接口定义 |

### 4.2 API 字段匹配

对每个字段，在 API 文档中搜索：

```
1. 用字段英文名（如有）精确匹配 API 字段
2. 用字段中文名匹配 API 说明文字
3. 用 prdKeyword 匹配 API 参数说明
```

### 4.3 API 提取内容

找到匹配后，提取：

```json
{
  "apiFieldName": "API 字段英文名",
  "apiType": "API 字段类型（string/number/boolean/object）",
  "endpoint": "接口地址",
  "method": "请求方法（GET/POST/PUT/DELETE）",
  "paramType": "参数类型（query/body/path）",
  "required": "API 是否必填（Y/N）",
  "example": "示例值",
  "enum": "枚举值（如有）",
  "confidence": "匹配置信度（high/medium/low）"
}
```

### 4.4 三源优先级规则（重要）

**当 PRD、设计图、API 三者定义冲突时，按以下优先级处理：**

| 维度 | 以谁为准 | 说明 |
|------|---------|------|
| 字段名/枚举值（伪代码） | **API** | 设计图标注了伪代码字段名（如 `applicant`）但 API 实际叫 `applicantName`，以 API 为准 |
| 必填性 | **PRD** | PRD 明确定义了哪些字段必填，这是业务需求，不以设计图或 API 为准 |
| 字段是否缺失 | **PRD** | PRD 定义的字段必须存在，PRD 未定义但设计图/API 有的字段标记为"补充字段" |
| 字段类型/组件 | **设计图** | 设计图定义了 UI 呈现方式，但伪代码部分（如枚举值）以 API 为准 |

#### 伪代码字段名冲突处理

设计图中常使用简写或非标准字段名，当检测到伪代码与 API 不一致时：

```
处理逻辑：
1. 比较设计图字段名与 api.apiFieldName
2. 不一致时：
   - 字段名以 API 为准（文档中写 apiFieldName）
   - 在字段清单的"事件流"或"PRD 说明"列中标注：
     **注意**：设计图字段名为 `xxx`，API 字段名为 `yyy`
3. 枚举值冲突时：
   - 以 API 枚举值为准
   - 标注设计图与 API 的差异
```

示例：
```
设计图：字段名 applicant，枚举 draft/approving/rejected/approved
API：   字段名 applicantName，枚举 DRAFT/PROCESSING/REJECTED/COMPLETED/CLOSED

输出：
- 字段名写 applicantName（以 API 为准）
- 枚举写 DRAFT/PROCESSING/REJECTED/COMPLETED/CLOSED（以 API 为准）
- 注意列标注：设计图字段名为 applicant，设计图枚举为 draft/approving/rejected/approved
```

### 4.5 下拉字段数据源检测（重要）

**对于 Select 类型字段，必须检测其是否有对应的数据源接口。**

#### 检测逻辑

```
对每个 Select 组件字段：
1. 检查是否有字典编码 → 字典接口获取选项
2. 检查是否有独立的数据源接口（如组织架构接口）
3. 两者都没有 → 记录为 missingDataSource，加入缝隙清单
4. 有联动关系（如分公司→区域）→ 记录联动配置
```

#### 常见数据源映射

| 字段类型 | 数据来源 | 典型接口 |
|---------|---------|---------|
| 字典类（审批状态、业态等） | 字典接口 | `/api/myth-permission/v3/dict/data/list` |
| 组织类（分公司、区域） | 组织架构接口 | `/api/myth-permission/v3/secOrg/findOrgIncludeSub` |
| 用户类（申请人、负责人） | 用户接口 | 用户搜索 API |
| 项目类（项目名称、编号） | 项目接口 | 项目搜索 API |

#### 输出要求

检测到缺失数据源的 Select 字段时：
1. **在缝隙清单中记录**：标记为 `missingDataSource`
2. **在输出文档中保留位置**：字段行正常输出，但在说明列标注 `[待确认：未找到对应的数据源接口，需确认数据来源]`
3. **生成时主动提示用户**：告知哪些 Select 字段未找到数据源接口，请用户确认

联动字段检测：
```json
{
  "label": "区域",
  "component": "Select",
  "linkage": {
    "dependsOn": "branchCompany",
    "clearOnChange": true
  },
  "dataSource": {
    "type": "org",
    "found": false,
    "note": "未找到区域下拉数据源接口，需确认"
  }
}
```

## 5. 匹配置信度判定

### 5.1 字段匹配置信度

| 等级 | 条件 |
|------|------|
| **high** | 第 1 轮精确匹配成功，字段英文名和规则都找到 |
| **medium** | 第 2-3 轮匹配成功，规则部分找到 |
| **low** | 第 4 轮匹配成功，仅找到通用规则 |
| **unmatched** | 4 轮都未找到 |

### 5.2 按钮匹配置信度

| 等级 | 条件 |
|------|------|
| **high** | 第 1 轮匹配成功，点击行为和校验规则都找到 |
| **medium** | 第 1 轮匹配成功，仅找到点击行为 |
| **low** | 第 2 轮匹配成功 |
| **unmatched** | 2 轮都未找到 |

### 5.3 API 匹配置信度

| 等级 | 条件 |
|------|------|
| **high** | 英文名精确匹配，类型和端点都找到 |
| **medium** | 中文名匹配，端点找到 |
| **low** | prdKeyword 匹配，仅找到端点 |
| **unmatched** | 都未找到 |

## 6. 缝隙分析（Gap Analysis）

### 6.1 PRD 未明确字段

```
条件：prd.confidence = "low" 或 "unmatched"
记录内容：
- page: 页面名称
- module: 模块名称
- label: 字段中文名
- type: "field"
- reason: 未匹配原因
```

### 6.2 API 未定义字段

```
条件：api 为 null 或 api.confidence = "unmatched"
记录内容：
- page: 页面名称
- module: 模块名称
- label: 字段中文名
- type: "field"
- reason: "未提供 API 文档" 或 "API 文档中未定义"
```

### 6.3 PRD 矛盾项

```
条件：同一字段在不同章节的描述不一致
记录内容：
- page: 页面名称
- module: 模块名称
- label: 字段中文名
- type: "conflict"
- conflictDesc: "在{章节 A}描述为{值 A}，在{章节 B}描述为{值 B}"
- suggestion: "暂以{章节 X}为准"
```

## 7. 特殊情况处理

### 7.1 字段名多义性

当字段名在 PRD 中出现多次（多义性）：

```
处理规则：
1. 优先匹配同页面的描述
2. 其次匹配同模块类型的描述
3. 都无法匹配时，记录为"多义性字段"，在缝隙清单中标注
```

### 7.2 业态驱动字段

当字段随业态动态变化：

```
提取规则：
1. 记录各业态下的字段名称变体
2. 记录各业态下的必填性差异
3. 记录各业态下的精度差异
```

**示例**：
```
字段：容量
- 风电业态：capacityTotal（必填，MW，2 位小数）
- 光伏业态：capacityPv、capacityPvDc（必填，MWp，2 位小数）
- 储能业态：energyScale、storageCapacity（必填，MW/MWh，2 位小数）
```

### 7.3 审批页字段

审批页字段的只读性随审批节点变化：

```
提取规则：
1. 记录每个审批节点的可编辑字段
2. 字段对象中添加 `editableNodes` 数组
3. 在 output 中生成"可编辑节点"列
```

## 8. 质量检查清单

Indexer 输出前确认：
- [ ] 所有字段都执行了 PRD 四轮检索
- [ ] 所有按钮都执行了 PRD 两轮检索
- [ ] 匹配置信度标注正确
- [ ] PRD 锚点格式正确（# 章节号 - 描述）
- [ ] 字段英文名已提取（或标注"未明确"）
- [ ] 必填/只读规则已提取
- [ ] 精度/格式已提取
- [ ] 字典已提取（或标注"未明确"）
- [ ] 缝隙清单完整
- [ ] API 检索（如有）完成
- [ ] 矛盾项已标注
- [ ] 业务规则已提取（如有）

## 9. 业务规则提取策略

### 9.1 搜索关键词

```
关键词组 1（业务背景）：
- "业务流程"、"业务背景"、"功能概述"、"功能说明"
- "适用于"、"用于"、"目的"

关键词组 2（校验规则）：
- "校验"、"验证"、"提交申请时"、"提交时校验"
- "必须先"、"前置条件"、"前提条件"
- "不允许"、"限制"

关键词组 3（失败提示）：
- "提示"、"提醒"、"告知"
- "请先"、"尚未"、"未完成"
```

### 9.2 搜索范围

```
1. PRD 的"功能方案"章节（通常是 4.x.x 节的概述部分）
2. PRD 的"与其他应用/功能关系"章节
3. PRD 中"提交"按钮的校验规则描述
4. PRD 中"补充逻辑"章节
```

### 9.3 提取内容

```json
{
  "background": "从 PRD 功能概述中提取业务背景描述（1-3句话）",
  "validationRules": ["从 PRD 校验规则段落中逐条提取"],
  "failMessages": ["从 PRD 中提取校验失败时的提示文案"]
}
```

### 9.4 输出条件

- 仅在搜索到至少 1 条校验规则或失败提示时输出 `businessRules`
- 如果只找到背景描述没有校验规则，只输出 `background` 字段
- 如果完全未找到相关内容，不输出 `businessRules` 字段
