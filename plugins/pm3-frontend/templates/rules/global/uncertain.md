
# 模糊场景处理指南

> 当遇到以下情况时，**停止执行，询问用户确认**

---

## 触发条件（满足任一即停止）

| 编号 | 场景描述 | 示例 |
|:---|:---|:---|
| U1 | 无法确定页面类型 | "开发一个页面，有列表又能编辑" |
| U2 | 无法确定场景归属 | "弹窗里嵌套了表格，表格里又能编辑" |
| U3 | 需求与现有模式冲突 | "列表页不需要分页" / "表单页不需要校验" |
| U4 | 涉及未定义的特殊交互 | "版本对比要左右滑动对比" / "审批需要电子签章" |
| U5 | 技术栈与规范冲突 | "需要用 template 语法" / "需要用 Options API" |

---

## 询问模板

当触发以上条件时，按以下格式询问用户：

```
遇到模糊场景，需要确认：

**需求描述**：{用户原始需求}

**识别到的矛盾**：
- {矛盾点 1}
- {矛盾点 2}

**可选方案**：
A. {方案 A 描述} → 对应规则：{文件}
B. {方案 B 描述} → 对应规则：{文件}
C. 其他（请描述）

请确认采用哪个方案？
```

## 规则沉淀流程

```
遇到模糊场景
    ↓
询问用户确认
    ↓
记录到「已记录的模糊场景」
    ↓
如果复用次数 >= 3 次
    ↓
沉淀为正式规则文件（scene-*.md 或 pattern-*.md）
```

---

## 绝对禁止（无需确认）

以下行为**直接拒绝**，不进入模糊场景处理：

- ❌ 使用 `render()` 函数
- ❌ 在 TSX 中使用 `this`
- ❌ 使用 `check.md` 中「禁止」列表的组件
- ❌ 在 `defineComponent` 中写 `components` 配置
